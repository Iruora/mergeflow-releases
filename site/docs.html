    This removes the quarantine flag macOS adds to downloaded files. Alternatively, try to open the app once, then go to System Settings › Privacy & Security and click Open Anyway.
  3. Open Mergeflow. Later versions install themselves (see Updates), so this step is only needed for the first install.

Connect GitLabConnecter GitLab

On first launch, Mergeflow asks for your GitLab address and a personal access token.

  1. GitLab address: https://gitlab.com by default. For a self-hosted server, enter its address, including a path prefix if it has one (https://git.example.com/gitlab). Only https is accepted, except for localhost.
  2. Token: in GitLab, open your avatar › Edit profile › Access tokens › Add new token. Give it a name and an expiry date, and tick only the read_api scope. Copy the token and paste it into Mergeflow.
  3. Mergeflow checks the address and the token, and tells you exactly what is wrong if something fails: bad address, expired token, missing scope, proxy or certificate problem, timeout.

The token is encrypted with your system keychain (macOS Keychain, Windows DPAPI) and never leaves the main process. Mergeflow only reads from GitLab: it never approves, merges or comments. You can change the address or token later in Settings › GitLab connection. Mergeflow warns you 7 and 3 days before the token expires.

Au premier lancement, Mergeflow demande l'adresse de votre GitLab et un jeton d'accès personnel.

  1. Adresse GitLab : https://gitlab.com par défaut. Pour un serveur auto-hébergé, saisissez son adresse, avec son préfixe de chemin s'il en a un (https://git.example.com/gitlab). Seul https est accepté, sauf pour localhost.
  2. Jeton : dans GitLab, ouvrez votre avatar › Modifier le profil › Jetons d'accès › Ajouter un jeton. Donnez-lui un nom et une date d'expiration, et cochez seulement le scope read_api. Copiez le jeton et collez-le dans Mergeflow.
  3. Mergeflow vérifie l'adresse et le jeton, et dit précisément ce qui ne va pas en cas d'échec : adresse invalide, jeton expiré, scope manquant, proxy, certificat, délai dépassé.

Le jeton est chiffré avec le trousseau du système (Trousseau macOS, DPAPI Windows) et ne quitte jamais le processus principal. Mergeflow ne fait que lire GitLab : il n'approuve, ne fusionne et ne commente jamais. Vous pouvez changer l'adresse ou le jeton dans Réglages › Connexion GitLab. Mergeflow vous prévient 7 et 3 jours avant l'expiration du jeton.

The queueLa file

By default, the dashboard lists the open, non-draft merge requests of your projects that GitLab reports mergeable, or that wait only on reviewers: missing approvals, unresolved threads, changes requested, or a pipeline still running. MRs with conflicts, a needed rebase, a failed pipeline or a policy block stay out until their author fixes them. You can change which states show in Settings > Queue rules, and Restore defaults puts these rules back. Ready notifications are only sent for MRs GitLab can merge.

The order is: urgent, then stale, then needs final approval, then severity label, then longest in the queue.

  • Urgent: the MR carries your urgent label (urgent by default).
  • Stale: the MR has been in the queue longer than your threshold (24 hours by default). The clock starts when Mergeflow first sees the MR ready. For MRs already ready on the first sync, the last update time is used and shown with "~".
  • Approvals: when a project sets no required approvals (GitLab Free), Mergeflow assumes two.

Use the sidebar views (urgent, getting stale, needs approval, approved by me), the project, author and team filters, the sort control, or search with Ctrl K (⌘ K on a Mac). The queue syncs every 3 minutes by default, and the refresh button syncs now.

Par défaut, le tableau de bord liste les merge requests ouvertes, hors brouillons, de vos projets que GitLab déclare fusionnables, ou qui n'attendent que des relecteurs : approbations manquantes, fils non résolus, modifications demandées, ou pipeline en cours. Les MR en conflit, à rebaser, au pipeline échoué ou bloquées par une règle restent hors de la file jusqu'à ce que l'auteur corrige. Vous pouvez choisir les états affichés dans Réglages > Règles de la file, et Rétablir les valeurs par défaut remet ces règles. Les notifications « prête » ne partent que pour les MR que GitLab peut fusionner.

L'ordre est : urgentes, puis en retard, puis dernière approbation attendue, puis label de gravité, puis ancienneté dans la file.

  • Urgente : la MR porte votre label d'urgence (urgent par défaut).
  • En retard : la MR est dans la file depuis plus longtemps que votre seuil (24 heures par défaut). Le compteur part du moment où Mergeflow voit la MR prête. Pour les MR déjà prêtes à la première synchronisation, la date de dernière mise à jour sert d'estimation, affichée avec « ~ ».
  • Approbations : quand un projet n'exige aucune approbation (GitLab Free), Mergeflow en suppose deux.

Utilisez les vues de la barre latérale (urgentes, bientôt en retard, à approuver, approuvées par moi), les filtres par projet, auteur et équipe, le tri, ou la recherche avec Ctrl K (⌘ K sur Mac). La file se synchronise toutes les 3 minutes par défaut, et le bouton d'actualisation la synchronise tout de suite.

Jira

Jira is optional. In Settings › Jira, enter your Jira address and:

  • Jira Cloud (https://your-site.atlassian.net): your Atlassian email and an API token, created at id.atlassian.com › Security › API tokens.
  • Jira Data Center or Server: a personal access token (your avatar › Profile › Personal Access Tokens), and leave the email empty.

Any MR whose title, labels or source branch contains an issue key such as PAY-142 gets a status badge on its card, and the details view shows the ticket's summary, status, type, priority, assignee and description. Tickets are cached for 5 minutes. If Jira is slow or a ticket is missing, the GitLab queue still syncs normally. The Jira token is encrypted like the GitLab one.

Jira est facultatif. Dans Réglages › Jira, saisissez l'adresse de votre Jira et :

  • Jira Cloud (https://votre-site.atlassian.net) : votre e-mail Atlassian et un jeton d'API, créé sur id.atlassian.com › Sécurité › Jetons d'API.
  • Jira Data Center ou Server : un jeton d'accès personnel (votre avatar › Profil › Jetons d'accès personnels), en laissant l'e-mail vide.

Toute MR dont le titre, les labels ou la branche source contiennent une clé de ticket comme PAY-142 reçoit un badge de statut sur sa carte, et le détail affiche le résumé, le statut, le type, la priorité, l'assigné et la description du ticket. Les tickets sont gardés en cache 5 minutes. Si Jira est lent ou qu'un ticket manque, la file GitLab se synchronise normalement. Le jeton Jira est chiffré comme celui de GitLab.

AI reviewRevue IA

AI review is off by default. Turn it on in Settings › AI review. Mergeflow does not ship a model or an account: it uses the CLI you already have and are signed in to.

Requirements

  • Claude Code v2.1.259 or later, signed in (claude auth status), or GitHub Copilot CLI, signed in.
  • Mergeflow finds the CLI on your PATH, in the usual install folders and, on macOS, in your login shell's PATH. You can also set its path in Settings.

Run a review

Click the review button on an MR card. In the start dialog, pick:

  • An agent, from ~/.claude/agents/ or ~/.copilot/agents/*.agent.md, or none to use Mergeflow's own reviewer. The agent in Settings is the default, and Mergeflow remembers the one you pick for each MR.
  • A skill, from ~/.claude/skills/<name>/SKILL.md, ~/.copilot/skills/, extra folders you add in Settings › AI review › Skill folders, or skills committed in the MR's own repository. Mergeflow adds the SKILL.md instructions to the prompt; scripts and reference files are not used.
  • A base branch: the MR's target branch by default, or any other remote branch.

Mergeflow's Clean Code reviewer

When no agent is picked, Mergeflow's reviewer follows Clean Code and SOLID: a summary with a verdict, a check against the MR description and Jira ticket, Mermaid diagrams of the change, findings grouped Critical, Major, Minor and Nit with file, class, method and line, why each is a problem and how to fix it, then missing tests. It writes in the app's language.

What is reviewed, and where it goes

  • Only lines the MR adds or changes. Findings that point only at untouched lines are moved to a separate section at the end.
  • The diff comes from GitLab and goes to the CLI on standard input only. The CLI runs in an empty temporary folder with every tool and MCP server off, so it cannot run commands, write files or browse.
  • Reviews are saved as Markdown on your computer (the last 5 per MR) and marked "outdated" when the MR gets new commits. Nothing is posted to GitLab.

Behind a company proxy

The CLIs connect to their own services. If a review stops with a network or certificate error, set the proxy in Settings › AI review › Network › Proxy (for example http://proxy.example.com:8080), and choose your company root certificate file there if your network inspects HTTPS. You can also set the HTTPS_PROXY, HTTP_PROXY, NO_PROXY and NODE_EXTRA_CA_CERTS environment variables for your user, then restart Mergeflow. On macOS, Mergeflow reads them from your login shell (~/.zshrc).

La revue IA est désactivée par défaut. Activez-la dans Réglages › Revue IA. Mergeflow ne fournit ni modèle ni compte : il utilise la CLI que vous avez déjà, et à laquelle vous êtes connecté.

Prérequis

  • Claude Code v2.1.259 ou plus récent, connecté (claude auth status), ou GitHub Copilot CLI, connecté.
  • Mergeflow trouve la CLI dans le PATH, dans les dossiers d'installation habituels et, sur macOS, dans le PATH de votre shell de connexion. Vous pouvez aussi indiquer son chemin dans les Réglages.

Lancer une revue

Cliquez sur le bouton de revue d'une carte. Dans la fenêtre de lancement, choisissez :

  • Un agent, depuis ~/.claude/agents/ ou ~/.copilot/agents/*.agent.md, ou aucun pour utiliser le relecteur de Mergeflow. L'agent des Réglages est celui par défaut, et Mergeflow retient celui choisi pour chaque MR.
  • Un skill, depuis ~/.claude/skills/<nom>/SKILL.md, ~/.copilot/skills/, les dossiers ajoutés dans Réglages › Revue IA › Dossiers de skills, ou les skills présents dans le dépôt de la MR. Mergeflow ajoute les instructions du SKILL.md au prompt ; les scripts et fichiers de référence ne sont pas utilisés.
  • Une branche de base : la branche cible de la MR par défaut, ou toute autre branche distante.

Le relecteur Clean Code de Mergeflow

Sans agent, le relecteur de Mergeflow suit Clean Code et SOLID : un résumé avec un verdict, une vérification par rapport à la description de la MR et au ticket Jira, des diagrammes Mermaid du changement, des remarques classées Critical, Major, Minor et Nit avec fichier, classe, méthode et ligne, pourquoi c'est un problème et comment le corriger, puis les tests manquants. Il écrit dans la langue de l'application.

Ce qui est relu, et où ça va

  • Seulement les lignes ajoutées ou modifiées par la MR. Les remarques qui ne visent que des lignes inchangées sont déplacées dans une section à part, à la fin.
  • Le diff vient de GitLab et n'est transmis à la CLI que par l'entrée standard. La CLI tourne dans un dossier temporaire vide, sans aucun outil ni serveur MCP : elle ne peut ni lancer de commande, ni écrire de fichier, ni naviguer.
  • Les revues sont enregistrées en Markdown sur votre ordinateur (les 5 dernières par MR) et marquées « obsolètes » quand la MR reçoit de nouveaux commits. Rien n'est publié dans GitLab.

Derrière un proxy d'entreprise

Les CLI se connectent à leurs propres services. Si une revue s'arrête sur une erreur réseau ou de certificat, indiquez le proxy dans Réglages › Revue IA › Réseau › Proxy (par exemple http://proxy.example.com:8080), et choisissez-y le fichier du certificat racine de l'entreprise si votre réseau inspecte le HTTPS. Vous pouvez aussi définir les variables d'environnement utilisateur HTTPS_PROXY, HTTP_PROXY, NO_PROXY et NODE_EXTRA_CA_CERTS, puis redémarrer Mergeflow. Sur macOS, Mergeflow les lit dans votre shell de connexion (~/.zshrc).

UpdatesMises à jour

Installed copies check for a new version at launch and every 4 hours, download it in the background, and show Restart to update in the top bar. The update also installs the next time you quit. Your settings and tokens are kept.

  • macOS: updates install themselves. You only run the xattr command for the first install.
  • Windows installer: updates install themselves.
  • Windows portable zip: cannot update itself. It shows a Download button; replace the folder with the new zip.

Release candidates (versions such as 1.2.0-rc.1) are published as pre-releases. Stable installs never move to them; a release candidate install moves to newer candidates and then to the final version.

Les copies installées cherchent une nouvelle version au lancement et toutes les 4 heures, la téléchargent en arrière-plan et affichent Redémarrer pour mettre à jour dans la barre du haut. La mise à jour s'installe aussi à la prochaine fermeture. Vos réglages et jetons sont conservés.

  • macOS : les mises à jour s'installent toutes seules. La commande xattr ne sert qu'à la première installation.
  • Installeur Windows : les mises à jour s'installent toutes seules.
  • Zip portable Windows : ne peut pas se mettre à jour. Il affiche un bouton Télécharger ; remplacez le dossier par le nouveau zip.

Les versions candidates (comme 1.2.0-rc.1) sont publiées en préversion. Une installation stable n'y passe jamais ; une installation candidate passe aux candidates suivantes, puis à la version finale.

Privacy and securityConfidentialité et sécurité

  • No account, no Mergeflow server, no analytics. The app talks only to your GitLab, your Jira, GitHub for updates, and, if you turn on AI review, the CLI you chose.
  • Tokens are encrypted with the system keychain and never reach the app's window. The settings file is readable only by you.
  • A read_api token is all Mergeflow needs, and it never writes to GitLab.
  • The window is sandboxed, opens links only in your browser (http and https only), and never loads remote images.
  • This website uses no cookies and no trackers. Your language and theme choices are kept in your browser only.
  • Pas de compte, pas de serveur Mergeflow, pas de statistiques. L'application ne parle qu'à votre GitLab, votre Jira, GitHub pour les mises à jour et, si vous activez la revue IA, la CLI choisie.
  • Les jetons sont chiffrés avec le trousseau du système et n'atteignent jamais la fenêtre de l'application. Le fichier de réglages n'est lisible que par vous.
  • Un jeton read_api suffit, et Mergeflow n'écrit jamais dans GitLab.
  • La fenêtre est isolée (sandbox), n'ouvre les liens que dans votre navigateur (http et https seulement) et ne charge jamais d'image distante.
  • Ce site n'utilise ni cookies ni traceurs. Vos choix de langue et de thème restent dans votre navigateur.

FAQ and troubleshootingFAQ et dépannage

Is Mergeflow free?

Yes. Download it and use it with as many projects as you like.

Mergeflow est-il gratuit ?

Oui. Téléchargez-le et utilisez-le avec autant de projets que vous voulez.

Does it work with self-hosted GitLab?

Yes, GitLab.com and self-managed GitLab, including servers under a path prefix. The server must use https, except on localhost. Corporate proxies set with HTTPS_PROXY are honoured.

Fonctionne-t-il avec un GitLab auto-hébergé ?

Oui, GitLab.com et GitLab auto-hébergé, y compris sous un préfixe de chemin. Le serveur doit être en https, sauf en localhost. Les proxys d'entreprise définis par HTTPS_PROXY sont pris en compte.

Why is a merge request missing from the queue?

With the default queue rules, the queue only shows open, non-draft MRs that can be merged or that wait only on reviewers. Drafts, conflicts, a needed rebase, a failed pipeline or a policy block keep an MR out until its author fixes it; you can let them in from Settings > Queue rules. Also check that its project is followed (Manage projects) and that no filter is active.

Pourquoi une merge request n'apparaît-elle pas ?

Avec les règles par défaut, la file ne montre que les MR ouvertes, hors brouillons, fusionnables ou qui n'attendent que des relecteurs. Un brouillon, un conflit, un rebase nécessaire, un pipeline échoué ou une règle bloquante écartent la MR jusqu'à ce que l'auteur corrige ; vous pouvez les inclure dans Réglages > Règles de la file. Vérifiez aussi que son projet est suivi (Gérer les projets) et qu'aucun filtre n'est actif.

macOS says Mergeflow "is damaged"

The app is not notarized by Apple yet. Run xattr -cr /Applications/Mergeflow.app in Terminal, or use Open Anyway in System Settings › Privacy & Security. See Install on macOS.

macOS dit que Mergeflow « est endommagé »

L'application n'est pas encore notarisée par Apple. Lancez xattr -cr /Applications/Mergeflow.app dans le Terminal, ou utilisez Ouvrir quand même dans Réglages Système › Confidentialité et sécurité. Voir Installer sur macOS.

Windows shows a SmartScreen warning

The app is not signed with a Microsoft certificate yet. Click More info, then Run anyway.

Windows affiche un avertissement SmartScreen

L'application n'est pas encore signée par un certificat Microsoft. Cliquez sur Informations complémentaires, puis Exécuter quand même.

Notifications do not show up

Send a test from Settings. Then allow notifications for Mergeflow in your system settings and turn off Focus or Do Not Disturb. See Notifications.

Les notifications ne s'affichent pas

Envoyez un test depuis les Réglages. Puis autorisez les notifications de Mergeflow dans les réglages du système et désactivez Concentration ou Ne pas déranger. Voir Notifications.

Mergeflow is slow to start

Each launch writes its timings to startup.log in the logs folder (~/Library/Logs/Mergeflow on macOS, %APPDATA%\Mergeflow\logs on Windows). A long delay before "main script running" comes from outside the app, usually antivirus scanning or a slow disk.

Mergeflow est lent à démarrer

Chaque lancement écrit ses temps dans startup.log, dans le dossier des journaux (~/Library/Logs/Mergeflow sur macOS, %APPDATA%\Mergeflow\logs sous Windows). Un long délai avant « main script running » vient d'en dehors de l'application, en général l'antivirus ou un disque lent.

An update does not arrive

Updates are checked at launch and every 4 hours. The portable Windows zip never updates itself. The updater writes to updater.log in the same logs folder.

Une mise à jour n'arrive pas

Les mises à jour sont vérifiées au lancement et toutes les 4 heures. Le zip portable Windows ne se met jamais à jour. Le programme de mise à jour écrit dans updater.log, dans le même dossier de journaux.

An AI review fails with a network or certificate error

Your network probably needs a proxy or inspects HTTPS. See Behind a company proxy.

Une revue IA échoue sur une erreur réseau ou de certificat

Votre réseau a sans doute besoin d'un proxy ou inspecte le HTTPS. Voir la partie proxy de la section Revue IA.

Where are my settings stored?

In ~/Library/Application Support/Mergeflow on macOS and %APPDATA%\Mergeflow on Windows. Tokens in that folder are encrypted. Uninstalling the app keeps it; delete the folder to start fresh.

Où sont enregistrés mes réglages ?

Dans ~/Library/Application Support/Mergeflow sur macOS et %APPDATA%\Mergeflow sous Windows. Les jetons y sont chiffrés. Désinstaller l'application garde ce dossier ; supprimez-le pour repartir de zéro.
